# Assignment：基于 Agent 的仿真抓取系统

## 1. 任务目标

输入一条自然语言指令，系统在随机桌面布局中识别指定对象，规划并执行抓取，
将目标稳定抬离桌面或放入指定容器，并输出可复现的过程证据。

场景固定包含单 Franka Panda、平行夹爪、桌面、两种容器和随机摆放物体。作业分三个递进
任务：Task 1 将红方块、绿圆柱、蓝长方体按指令放入方盘或圆盘；Task 2 抓取带材质的
YCB 香蕉或苹果，并放入指定方盘或圆盘；Task 3 将水果归圆盘、包装食品归方盘。每回合物体和容器位置、非香蕉物体
yaw 随种子变化；香蕉保持固定的可夹取躺卧朝向，避免把夹爪朝向偶然性误当作语言/视觉能力。
指令有中英文改写。完整任务与通过条件见 `STAGED_TASKS_ZH.md`。

## 2. 必须形成的闭环

```text
自然语言任务
  -> 目标 grounding / 感知
  -> 结构化目标与置信度
  -> IK / 规划 / policy
  -> 机械臂与夹爪执行
  -> 成功验证 / 失败分类
  -> 重试、重规划或安全停止
```

只播放一条手工轨迹、直接读取 `TaskSpec.target`、固定写死物体坐标，均不算闭环。

## 3. 允许的方法

可任选或组合：

- LLM 指令理解 + SAM/检测模型 + RGB-D 几何恢复 + 数值 IK；
- 商用/开源 VLM 识别图像中的目标 + RGB-D 几何 + IK；
- 检测/分割模型 + 深度反投影 + 抓取状态机；
- VLA 从视觉、语言和本体状态直接输出末端增量或关节目标；
- LLM Agent 调用感知、规划、执行、验证工具，并在失败后重规划。

评分看闭环、证据、实验和方法合理性，不按模型价格或参数量加分。使用远端 API 时必须
有超时、缓存、结构校验和安全回退，且不能把远端调用放进高频物理循环。

## 4. 接口契约

实现 `policies/student_policy.py` 中的：

```python
class StudentPolicy:
    def reset(self, task: dict, model: mujoco.MjModel) -> None: ...
    def act(self, observation: Observation) -> PolicyDecision: ...
```

政策只能看到 `task.public_dict()`，其中没有答案 `target`。每步必须返回：

- 数值动作；
- 当前 `stage`；
- 简短、可审计的 `rationale`；
- 已 grounding 的 `target_id`（确定后填写）；
- `done`、`request_retry` 和可选 debug 字段。

默认环境接受 `JointPositionCommand`。VLA 可输出 `CartesianDeltaCommand`，再用
`CartesianDeltaAdapter` 转成关节位置命令。

标准 `grasp-eval` 默认将 `act()` 放在单一异步 worker 中，并以 25 Hz 持续推进物理。模型未返回时
框架只会短暂复用上一命令，随后保持当前关节位置；状态漂移后的结果不会执行。学生不需要自行开
线程，必须把远端调用设计成事件触发而非每个控制步调用。完整约束见 `ASYNC_CONTROL_ZH.md`。

## 5. 最小验收条件

- 在一台普通笔记本上从 README 命令安装并运行；
- 三个公开任务集均可重复评测，不能只交视频；
- 正确选中自然语言指定目标和容器；Task 3 需完成整套类别分拣；
- 至少显式包含 PREGRASP、APPROACH/DESCEND、CLOSE、LIFT、PLACE（如需要）、VERIFY；
- 至少一种失败能触发重试、重规划或安全停止；
- 日志能够定位感知、规划、控制、验证中的最早失败点；
- 报告含成功率、目标选择准确率、步数/耗时、失败类型和至少一个对照实验。

## 6. 禁止事项

- 修改公开评测器的成功判定以制造高分；
- 从任务文件或文件名直接查表返回目标；
- 删除失败回合，只报告成功视频；
- 在代码或报告中提交真实 API key；
- 依赖助教机器上的绝对路径、未声明模型或私人服务；
- 将随机种子当作目标标签或轨迹索引。

## 7. 建议开发节奏

1. 先让 starter、渲染、日志和单元测试运行；
2. 接通真实模型服务，让模型输出可审计的目标 mask/box/point；
3. 冻结控制器后替换感知/Agent，避免同时调所有模块；
4. 在 2–3 个 dev seed 调试；
5. 冻结 prompt、模型版本、score 门限和控制参数，在完整公开集一次性评测；
6. 记录失败 taxonomy，再做一个有控制变量的改进；
7. 最后录制视频、整理报告与分工。

## 8. 提交物

- 完整代码，保留本项目目录结构；
- README：一条安装命令、一条运行命令、一条复现评测命令；
- `requirements.txt` 或锁文件；
- 实验报告 PDF；
- 3–5 分钟演示视频；
- 一份代表性成功日志、一份失败日志、公开集 `aggregate.json`；
- `TEAM.md`：每个人的可核查贡献；
- 若使用 API：脱敏配置示例 `.env.example`，不提交 `.env`。

## 9. 可选拓展与课程边界

在完成三项基础任务后，可以选择 VLA 路线、人形机器人平台迁移，或结合课程内容提出主题相近的自选拓展。拓展必须仍以语言/视觉驱动的抓取或操控闭环为中心，并保留任务定义、物理成功条件、日志与对照实验。

不接受两类工作：一是偏离具身抓取/操控主题太多的项目；二是把个人或团队已准备投稿、正在投稿或已经投稿的研究工作直接作为课程成果。鼓励使用课程期间实现的新系统和新实验；公开模型与论文可以作为基线，但必须引用且清楚区分。详见 `docs/EXTENSIONS_AND_ACADEMIC_INTEGRITY_ZH.md`。
